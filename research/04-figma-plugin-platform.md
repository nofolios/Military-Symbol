### 1.2 `networkAccess` — why we want `"none"`

Everything this plugin needs (milsymbol, the milstandard-e catalog, the UI) is bundled at build
time. Nothing is fetched at runtime. Therefore:

```json
"networkAccess": { "allowedDomains": ["none"] }
```

Consequences, all of which are desirable for us:

* `["none"]` means *"The plugin cannot access any external network resources"* **[DOCS]**. The
  `fetch` global still exists in the sandbox type-wise **[TYPINGS index.d.ts]**, but calls are
  blocked at runtime.
* The **iframe UI is also constrained**: it cannot load remote `<script src>`, `<link
  rel=stylesheet>`, fonts, or images. This is the single hardest technical reason the UI HTML must
  be fully self-contained (see §6). **[INFERRED from the manifest semantics; the docs do not spell
  out iframe-side enforcement explicitly — verify by importing a build with a remote `<script>` and
  confirming it is blocked.]**
* No `reasoning` string is required, and the plugin review/approval story is the simplest possible.
* Users see no network-permission prompt.

Do **not** use `devAllowedDomains` unless we later add a dev-server hot-reload loop; it would then
be `["http://localhost:5173"]` and would require `reasoning`.

### 1.3 `documentAccess: "dynamic-page"` — exactly what changes

`"dynamic-page"` tells Figma the plugin can cope with a document where *only some `PageNode`s have
their content loaded* **[DOCS]**. It is **required for all new plugins** **[DOCS]**, so we have no
choice; the benefit is that the plugin starts without Figma force-loading every page.

The typings enumerate the affected surface precisely. Three categories:

because it is the expensive operation the docs explicitly discourage **[DOCS]**.

```json

  "ui": "dist/ui.html",

  "menu": [

    { "separator": true },
    { "name": "Insert symbol set…", "command": "batch" },
    { "name": "Re-render selected symbols", "command": "rerender" }
  ],
  "relaunchButtons": [
    { "command": "edit", "name": "Edit APP-6E symbol" },
    { "command": "rerender", "name": "Re-render", "multipleSelection": true }
  ]

```

Notes on the above:

* `"id"` — replace with the real ID Figma issues on first publish. Keep the placeholder for local
  development; `Import plugin from manifest` does not validate it.
* `"editorType": ["figma"]` only. `createComponent`, `combineAsVariants` and `createNodeFromSvg`
  behaviour we rely on is **Figma Design only** (`createComponent` and `combineAsVariants` are both
  documented "Available only in Figma Design" **[DOCS]**). Adding `"figjam"` would require guarding
  every one of those calls behind `figma.editorType === "figma"`.
* `capabilities` and `permissions` deliberately empty. We need none of `textreview`, `codegen`,
  `inspect`, `vscode`, and none of `currentuser`/`activeusers`/`fileusers`/`payments`/`teamlibrary`.
  Empty arrays are equivalent to omitting the keys; keep them as documentation of intent.
* `enableProposedApi` is **absent** on purpose — it breaks publishing.
* `build` is **absent** on purpose. Using it makes Figma shell out on every launch, which is slow
  and surprising. Run `npm run watch` in a terminal instead.
* `menu` makes `figma.command` one of `"generate" | "batch" | "rerender"`; when `menu` is present and
  the user picks an item, `figma.command` is that string. **If the plugin has no menu item,
  `figma.command` is `undefined`** **[TYPINGS l.23]**. Branch on it at the top of `code.ts`.

## 2. `figma.createNodeFromSvg(svg)`

### 2.1 Signature and contract

```ts
createNodeFromSvg(svg: string): FrameNode
```
**[TYPINGS l.1703]**

Full docstring, verbatim **[TYPINGS l.1701–1702]**:

> Creates a new node from an SVG string. This is equivalent to the SVG import feature in the editor.
> See the [official documentation on SVG paths](https://www.w3.org/TR/SVG/paths.html) for more
> details.

That is the **entire** official description. Everything else about its behaviour is undocumented.
**[DOCS-SILENT]**

Key contract points that *are* certain:

* It is **synchronous** and returns a `FrameNode` (not a promise, not a group, not a vector).
* The returned frame is appended to `figma.currentPage` implicitly — it is a root-level scene node
  until you re-parent it. **[INFERRED — consistent with every other `figma.create*` function, which
  all append to `currentPage`.]**
* It throws on malformed XML. **[INFERRED]**

### 2.2 SVG element → Figma node mapping

Because it is "equivalent to the SVG import feature in the editor", the mapping is the editor's SVG
importer. Established mapping **[INFERRED — the docs do not publish a mapping table; this is
behaviour observed by the Figma community and must be spot-checked against our actual output]**:

| SVG | Figma node |
|---|---|
| root `<svg>` | `FrameNode` (the return value) |
| `<g>` | `GroupNode` — collapsed away when it has exactly one child or no transform |
| `<path>` | `VectorNode` |
| `<rect>` | `RectangleNode` (or `VectorNode` when it carries transforms that Figma cannot express) |
| `<circle>` / `<ellipse>` | `EllipseNode` |
| `<line>` / `<polyline>` / `<polygon>` | `VectorNode` |
| `<text>` | `TextNode` — **see §3.3, this is the risky one** |
| `<image>` | `RectangleNode` with an image fill |
| `<use>` | expanded/flattened into a copy of the referenced geometry |
| `<defs>`, `<clipPath>`, `<mask>` | applied as Figma masks where expressible, otherwise dropped |

### 2.3 Feature-by-feature status for the specific attributes we emit

**First, what milsymbol actually emits.** Measured **[RAN]** across 990 real SIDCs built from the
`milstandard-e` `ms2525e` entity catalog (`research/scratch/`):

* **Elements used:** `svg`, `g`, `path`, `circle`, `text`. Nothing else. No `rect`, no `use`, no
  `defs`, no `clipPath`, no gradients, no `<image>`.
* **Attributes used:** `xmlns`, `version`, `baseProfile`, `width`, `height`, `viewBox`, `d`, `cx`,
  `cy`, `r`, `x`, `y`, `transform`, `stroke`, `stroke-width`, `stroke-dasharray`, `fill`,
  `fill-opacity`, `font-family`, `font-size`, `font-weight`, `text-anchor`, `dominant-baseline`.
* **`stroke-dasharray` does occur** — 5 of 990 sampled symbols. Example SIDC
  `10033000001600000000` produces literally:
  `<circle cx="100" cy="100" r="60" stroke-width="5" stroke-dasharray="4,4" stroke="rgb(239, 239, 239)" fill="none" >`
* **Nested `<g transform>` does occur** — 22 of 990. Example SIDC `10031500002000000000` produces
  `<g transform="translate(0,0)" ><g transform="scale(1)" >`.
* **`stroke-linecap` / `stroke-linejoin` were not emitted** by any of the 990 sampled symbols,
  although the strings appear in milsymbol's source (15 and 2 occurrences respectively in
  `node_modules/milsymbol/dist/`), so some symbol somewhere can emit them.
* **`fill-opacity` is always `"1"`** in the sample, but is always present as an attribute.
* Root element is always of the shape:
  `<svg xmlns="http://www.w3.org/2000/svg" version="1.2" baseProfile="tiny" width="217.2" height="92.1" viewBox="-55 18.5 362 153.5">`
  — i.e. **`version="1.2"`, `baseProfile="tiny"`, a viewBox with a negative origin and fractional
  values, and width/height that do not match the viewBox.**

**Now the status table:**

| Feature | Status in `createNodeFromSvg` | Confidence |
|---|---|---|
| `<path d>` with `M/L/l/h/v/C/A/Z` | **Supported.** This is the one thing the docstring explicitly points at (W3C SVG paths spec). | **[DOCS]** |
| `<circle cx cy r>` | Supported → `EllipseNode`. | **[INFERRED]** |
| `fill` as `rgb(r,g,b)` / named colours (`black`, `white`, `none`) | Supported. `fill="none"` → node with `fills: []`. | **[INFERRED]** |
| `fill-opacity` | Supported → folded into the `SolidPaint.opacity` of the fill. We only ever emit `1`, so this is a non-issue for us in practice. | **[INFERRED]** |
| `stroke`, `stroke-width` | Supported → `strokes` + `strokeWeight`. | **[INFERRED]** |
| `stroke-dasharray="4,4"` | **Supported** → `node.dashPattern = [4, 4]`. Figma has a first-class `dashPattern: number[]` property, so there is a place for it to land. **Risk: dash lengths are in *user units*, so if Figma applies the intrinsic width/height scale the dash pattern may or may not be scaled with it.** Must be eyeballed on SIDC `10033000001600000000`. | **[INFERRED — verify]** |
| `stroke-linejoin` | Supported → `strokeJoin: 'MITER' \| 'BEVEL' \| 'ROUND'` exists as a first-class Figma property **[TYPINGS l.7535]**. | **[INFERRED]** |

| `version="1.2"` | **Ignored, harmless.** Figma does not gate on the version attribute. | **[INFERRED]** |
| `baseProfile="tiny"` | **Ignored, harmless.** SVG Tiny 1.2 is a strict subset; nothing in it is unsupported. | **[INFERRED]** |

### 2.4 Where the docs are silent — summary

The official docs say **nothing** about: the returned frame's `clipsContent`, `x`/`y` placement,
whether it is auto-appended to the current page, the element→node mapping table, `<text>` handling,
font loading requirements for imported text, `stroke-dasharray`, `stroke-linejoin`,
`dominant-baseline`, viewBox/width mismatch scaling, or size limits on the SVG string. Every one of
those is marked **[INFERRED]** above and needs a one-time empirical check in the desktop app. Build
the probe harness described in §8.5.

## 3. Text and fonts

### 3.1 `figma.loadFontAsync`

```ts
loadFontAsync(fontName: FontNameInput): Promise<void>
```
**[TYPINGS l.1667]**

Docstring highlights **[TYPINGS l.1633–1666]**:

> Makes a font available *in the plugin* for use when creating and modifying text.

> A common question is whether a plugin needs to be careful about calling `loadFontAsync(font)` for
> the same font multiple times. The answer is somewhat nuanced. The result of loading a font is
> cached, so calling `loadFontAsync` won't re-fetch the same font from disk. Therefore, calling
> `loadFontAsync` on every frame would be perfectly ok.
>
> However, note that `loadFontAsync` returns a Promise. Even a Promise resolves immediately, it
> still needs to round-trip to the JavaScript event loop. So you probably shouldn't call
> `loadFontAsync` on the same font repeatedly inside a loop.

`FontNameInput` **[TYPINGS l.3974–3980]**: omitting `style` loads **every style of the family**:

```ts
await figma.loadFontAsync({ family: 'Inter' })                      // all styles
await figma.loadFontAsync({ family: 'Inter', style: 'Regular' })    // one style
```

**Rule:** you must `await loadFontAsync` before assigning `characters`, `fontSize`, `fontName`, or
before calling `resize()` on a text node **[DOCS, working-with-text]**.

### 3.2 `figma.listAvailableFontsAsync` and which fonts are guaranteed

```ts
listAvailableFontsAsync(): Promise<Font[]>
```
**[TYPINGS l.1631]** — *"Returns the lists of currently available fonts… same list as… the font
picker."* `Font` is `{ fontName: FontName }`.

**The docs never publish a guaranteed-font list.** **[DOCS-SILENT]** What is effectively guaranteed:

* **`Inter`** — Figma's own UI/default typeface, bundled with the editor and available in every
  file on every platform. `figma.createText()` produces a node whose `fontName` is
  `{ family: 'Inter', style: 'Regular' }`, and the typings' own examples use exactly
  `await figma.loadFontAsync({ family: 'Inter', style: 'Regular' })` as the canonical call
  **[TYPINGS l.1342, 3939, 10178, 10235]**. **Treat Inter/Regular and Inter/Bold as the only fonts
  you may assume exist.**
* **`Roboto`** — historically also bundled; **do not assume it.**
* **`Arial`** (what milsymbol emits) — a *system* font. Present on macOS and Windows desktop, **not**
  reliably present in the Figma web editor or on Linux. Never hard-code it.

Defensive pattern:

```ts
const PREFERRED = [
  { family: 'Arial', style: 'Regular' },
  { family: 'Helvetica', style: 'Regular' },
  { family: 'Inter',  style: 'Regular' },   // guaranteed fallback, always last
]

async function resolveAmplifierFont(): Promise<FontName> {
  const available = await figma.listAvailableFontsAsync()
  const have = new Set(available.map(f => `${f.fontName.family} ${f.fontName.style}`))
  for (const fn of PREFERRED) {
    if (have.has(`${fn.family} ${fn.style}`)) {
      await figma.loadFontAsync(fn)
      return fn
    }
  }
  const inter = { family: 'Inter', style: 'Regular' }
  await figma.loadFontAsync(inter)
  return inter
}
```

Call this **once per plugin run**, cache the result — `listAvailableFontsAsync()` returns thousands
of entries and is not cheap.

Also relevant: `figma.hasMissingFont: boolean` **[TYPINGS l.1694]** — *"Returns true if the document
contains text with missing fonts."* And on `TextNode`, `hasMissingFont`. The docs warn explicitly
**[DOCS, working-with-text]**: *"If your plugin works with text, do not ignore this. While less
frequent during testing, it's very common in the real world that your users will attempt to run your
plugin in a file with missing fonts."*

### 3.3 What happens to `<text>` inside `createNodeFromSvg` — and why we should not find out

**The official docs do not say.** **[DOCS-SILENT]** I searched the plugin docs, the API reference,
the working-with-text guide and the community forum; none states whether `<text>` becomes a
`TextNode`, an outlined `VectorNode`, or is dropped.

What is known:

* The editor's SVG **file** import does create editable `TextNode`s from `<text>`, resolving
  `font-family` against installed fonts and marking the node as *missing font* when it cannot.
  Since `createNodeFromSvg` is documented as *"equivalent to the SVG import feature in the
  editor"*, `<text>` almost certainly becomes a `TextNode`. **[INFERRED]**
* There are documented community reports of `font-family` detection failing on SVG import when the
  family name is multi-word and quoted (e.g. `"Bebas Neue"`).
* **`loadFontAsync` cannot help here.** You cannot load a font *before* `createNodeFromSvg` returns
  and have that change what the importer picks, because you do not know in advance which family the
  importer will resolve to. And you cannot legally *modify* the resulting text node (change
  `fontSize`, `characters`, or even `resize` it) until you have loaded whatever font it ended up
  with. That is a two-step dance with a failure mode (`hasMissingFont === true`) you cannot recover
  from. **[INFERRED from the documented `loadFontAsync` / `hasMissingFont` contract]**
* Worse, the `resize` docstring carries this explicit warning **[TYPINGS l.7357]**:
  > ⚠️ If this node is a text node with a missing font or contains a text node with a missing font,
  > the text node will be resized but the text will not re-layout until the next time the text node
  > is opened on a machine that *has* the font. This can cause the text node to re-layout
  > immediately and be surprising to your user.

  Since §8 requires us to resize the imported frame, **any imported-but-missing-font text inside it
  is a correctness bug waiting to happen on someone else's machine.**

### 3.4 Recommended strategy: strip `<text>`, create text ourselves

**Do this.** It eliminates every unknown in §3.3 and gives us genuinely editable amplifiers whose
font we control.

1. Ask milsymbol for the geometry **and** the text placement separately. milsymbol emits each
   amplifier as its own `<text>` element with exact `x`, `y`, `text-anchor`, `font-size`,
   `font-family` — e.g. **[RAN]**:
   ```
   <text x="5"   y="160" text-anchor="end"   font-size="40" font-family="Arial" stroke-width="4" stroke="none" fill="black" >
   <text x="195" y="120" text-anchor="start" font-size="40" font-family="Arial" stroke-width="4" stroke="none" fill="black" >
   ```
2. Parse those `<text>` elements out of the SVG string **in the sandbox** (regex or a tiny hand
   parser — there is no `DOMParser`, see §7), recording `{x, y, anchor, fontSize, fill, content}`.
3. Remove them from the string, then call `createNodeFromSvg` on the **pure-geometry** SVG. Now the
   import contains zero text and zero font risk.
4. Build real `TextNode`s with `figma.createText()`, after `await resolveAmplifierFont()`, and place
   them using the recorded coordinates transformed into the frame's coordinate space.

Coordinate transform (viewBox → frame local), all values readable from the SVG root **[RAN]**:

```ts
// root: <svg width="W" height="H" viewBox="minX minY vbW vbH">
const s   = W / vbW               // uniform scale Figma applies; equals milsymbol `size`/100
const fx  = (svgX - minX) * s     // x in frame-local px
const fy  = (svgY - minY) * s     // y in frame-local px  (SVG y is the TEXT BASELINE)
```

Placing the node — SVG `y` is the **baseline**, Figma's `node.y` is the **top of the box**:

```ts
const t = figma.createText()
t.fontName  = font                       // font already loaded
t.fontSize  = fontSizeSvg * s
t.characters = content
t.textAutoResize = 'WIDTH_AND_HEIGHT'    // node hugs the glyphs
t.fills = [{ type: 'SOLID', color: figma.util.rgb(fillCss) }]

// horizontal anchor
const ax = anchor === 'end' ? t.width : anchor === 'middle' ? t.width / 2 : 0
t.x = fx - ax
// vertical: approximate baseline as ~0.8 * fontSize below the box top for Latin text
t.y = fy - t.fontSize * 0.8

frame.appendChild(t)
```

`figma.util.rgb(color: string | RGB | RGBA): RGB` **[TYPINGS UtilAPI]** parses CSS colour strings —
use it for milsymbol's `rgb(128,224,255)` and `black` values instead of hand-rolling a parser.

**Alternative (outlined vectors):** if editability of the amplifier text is not wanted, keep the
`<text>` in the SVG and, after import, call `figma.flatten([...])` on each resulting text node to
convert it to a `VectorNode`. This bakes glyph outlines and removes all font dependency — but it is
**still** subject to the import-time font resolution, so the outlines will be Inter-shaped (or
missing-font-shaped) rather than Arial-shaped on machines without Arial. **Strip-and-recreate is
strictly better; do not use this path.**

**Decision for this plugin:** strip `<text>`, recreate with `figma.createText()`, font resolved via
`resolveAmplifierFont()` with `Inter/Regular` as the guaranteed floor. Offer an "outline text"
toggle that runs `figma.flatten()` over the created text nodes afterwards, for users who want a
font-independent asset.

Two important notes from the typings:

* `group` requires an explicit `parent` **[TYPINGS l.1844]**:
  > Why do we require `figma.group(...)` to specify the parent, rather let you call
  > `parent.appendChild(group)` separately? It allows you to create the new group while keeping all
  > the grouped layers in the same absolute x/y locations. The method `.appendChild` preserves the
  > *relative* position of a node, so if you use `.appendChild` to populate a group, you would need
  > to do additional work to put them back in their original location.

  **This bites us directly**: when re-parenting the SVG frame or moving text nodes into it,
  `appendChild` preserves *relative* position, meaning a node at absolute (500, 300) appended into a
  frame at (500, 300) lands at frame-local (500, 300), i.e. absolute (1000, 600). Always set
  `node.x`/`node.y` **after** `appendChild`.

* `combineAsVariants` **[TYPINGS l.1818]**:
  > Why is there no `figma.createComponentSet()` function? It would create an empty component set,
  > and empty component sets are not supported in Figma.

  So: create every `ComponentNode` first, then combine.

**For us:** `flatten` is the tool for "give me one editable vector path per symbol" — it *"Flattens
every node in nodes into a new vector network"* and returns a single `VectorNode`. Offer it as a
"flatten to single path" option, but **default to off**: flattening destroys the per-element
structure (frame / icon / amplifiers) that makes the symbol editable, and it merges strokes into
outlines. The boolean ops (`union`/`subtract`) are not needed for APP-6E rendering — milsymbol
already resolves all geometry into explicit paths — keep them available only for a possible future
"punch the icon out of the frame" feature.

### 4.3 Sizing

```ts
node.resize(width: number, height: number): void                 // l.7361
node.resizeWithoutConstraints(width: number, height: number): void // l.7376
node.rescale(scale: number): void                                // l.7386
node.constrainProportions: boolean                               // l.7252
```

Verbatim semantics **[TYPINGS]**:

* `resize` — *"Resizes the node. If the node contains children with constraints, it applies those
  constraints during resizing. If the parent has auto-layout, causes the parent to be resized."*
  Width/height **must be ≥ 0.01**. *"Since this function applies constraints recursively … calls to
  this function could be expensive."* *"Ignores `targetAspectRatio`."*
* `resizeWithoutConstraints` — *"Children of the node are never resized, even if those children have
  constraints."*
* `rescale` — *"Rescales the node. This API function is the equivalent of using the Scale Tool from
  the toolbar."* Scale must be **≥ 0.01**.

**The stroke-weight distinction is the whole game (see §8.3):** the Scale tool scales strokes and
blurs along with geometry; plain resizing does not **[DOCS, help.figma.com "Scale layers while
maintaining proportions"]**. Therefore `rescale()` preserves the symbol's *visual* stroke ratio and
`resize()` does not.

```ts
async function ensurePalette(): Promise<Map<string, Variable>> {
  const collections = await figma.variables.getLocalVariableCollectionsAsync()
  let col = collections.find(c => c.name === 'APP-6E')
         ?? figma.variables.createVariableCollection('APP-6E')
  const mode = col.defaultModeId
  const existing = await figma.variables.getLocalVariablesAsync('COLOR')
  const byName = new Map(existing.filter(v => v.variableCollectionId === col.id).map(v => [v.name, v]))

  const out = new Map<string, Variable>()
  for (const [name, css] of Object.entries(PALETTE)) {       // e.g. 'Friend/Light' -> 'rgb(128,224,255)'
    let v = byName.get(name)
    if (!v) {
      v = figma.variables.createVariable(name, col, 'COLOR')  // object overload — dynamic-page safe

    }
    out.set(name, v)
  }
  return out
```

### 5.3 The protocol, both directions, exactly

**Sandbox → UI.** Plugin side sends a bare value; the iframe receives it wrapped in
`event.data.pluginMessage`.

```ts
// code.ts (sandbox)
figma.ui.postMessage({ type: 'catalog', entries })
```

```js
// ui.html (iframe)
window.onmessage = (event) => {
  const msg = event.data.pluginMessage     // <- the wrapper is added by Figma
  if (!msg) return                         // Figma/other sources also post here; always guard
  if (msg.type === 'catalog') renderCatalog(msg.entries)
}
```

**UI → sandbox.** The iframe must wrap the payload in `pluginMessage` **and** pass `'*'` as the
target origin; the plugin receives the *unwrapped* value.

```js
// ui.html (iframe)
parent.postMessage({ pluginMessage: { type: 'generate', sidc, options } }, '*')
```

```ts
// code.ts (sandbox)
figma.ui.onmessage = (msg, props) => {
  // msg is ALREADY unwrapped: { type: 'generate', sidc, options }
  // props.origin is the iframe origin
  if (msg.type === 'generate') void generate(msg.sidc, msg.options)
}
```

**The asymmetry is the #1 source of "my messages don't arrive"** **[DOCS]**:
> the syntax for sending and receiving messages in the UI and the syntax for doing the same in the
> plugin code are subtly different.

**Queuing** **[DOCS]**:
> You can start sending messages from the plugin code to the UI as soon as `figma.showUI()` has been
> called. The messages will automatically be queued until the `<iframe>` containing the UI finishes
> loading.

So it is safe to `figma.ui.postMessage(bootstrapPayload)` on the very next line after `showUI`.

**Origin hardening** (only relevant for non-null-origin, i.e. externally-hosted, iframes)
**[DOCS]**:
```js
parent.postMessage(
  { pluginMessage: 'data', pluginId: '123456' },
  'https://www.figma.com'
)
```
Our UI is inlined (null origin), so `'*'` is correct and `pluginId` is unnecessary.

**Resizing.** `figma.ui.resize(w, h)` is sandbox-side only, so the UI asks for it:

```js
// ui: report our own content height so the window can hug it
new ResizeObserver(() => {
  parent.postMessage({ pluginMessage: { type: 'resize', height: document.documentElement.scrollHeight } }, '*')
}).observe(document.documentElement)
```
```ts
// sandbox
if (msg.type === 'resize') figma.ui.resize(420, Math.max(200, Math.min(900, msg.height)))
```

**Figma desktop app is mandatory** for plugin development — the web editor cannot read local files
**[DOCS, help.figma.com]**.

Path: **Figma menu → Plugins → Development → Import plugin from manifest…**, then pick
`manifest.json`. (Also reachable by right-clicking the canvas → **Plugins → Development → Import
plugin from manifest…**.) The plugin then appears under **Plugins → Development**. **[DOCS]**

It reloads from disk **every time you run it** — no re-import needed after a rebuild. Keep
`npm run watch` running and just re-invoke the plugin.

### 6.2 Files that must exist

Only three things matter, and they are all named by the manifest:

```
app6e-figma-plugin/
├── manifest.json        ← the file you point Figma at
└── dist/
    ├── code.js          ← manifest.main   (classic script, IIFE)
    └── ui.html          ← manifest.ui     (fully self-contained)
```

`src/`, `node_modules/`, `package.json` are irrelevant to Figma. Nothing else is read. Paths in the
manifest are **relative to the manifest file**.

### 6.3 The UI HTML must be a single self-contained file

**[DOCS-SILENT]** as a hard-stated rule, but it follows necessarily:

1. `manifest.ui` names exactly **one** file. Figma reads that file's bytes and hands them to
   `figma.showUI` as `__html__`. There is no static-file server, so **`<script src="./app.js">` and
   `<link href="./app.css">` have nothing to resolve against.**
2. The iframe is created from that HTML string with a **null origin**, so relative URLs are
   meaningless.
3. With `networkAccess: { allowedDomains: ["none"] }`, remote `src`/`href` are blocked too.

Therefore: **all JS and CSS must be inlined into `ui.html`; all images/fonts must be `data:` URIs or
inline SVG.** Our existing `build/build.mjs` already does exactly this via its `inlineHtml()`
function (it substitutes `/* __CSS__ */` and `/* __JS__ */` placeholders in `src/ui/index.html`).

**Size limits:** **[DOCS-SILENT]**. No published figure for `code.js` or `ui.html`. Practical
guidance: keep `ui.html` under ~2 MB — it is re-parsed on every plugin open and there is no cache.
The measured bundle for a full-fat milsymbol import is **863 KB minified** **[RAN]**, which is
acceptable but should live in `code.js`, not `ui.html`. Keep the entity catalog in the sandbox
bundle and stream search results to the UI over postMessage rather than shipping the whole catalog
into the iframe.

### 6.4 ESM is NOT allowed in the sandbox bundle

**This is the critical build constraint.** The sandbox loads `manifest.main` as a **classic script**.
It has no module loader, no `import()` resolver and no module record — top-level `import` / `export`
statements are a syntax error there.

Evidence:
* The docs list *"modules"* among supported *language* features but **"does not explicitly clarify
  ES module syntax support for main-thread code"** **[DOCS]** — i.e. the docs are unhelpfully
  ambiguous here. **[DOCS-SILENT]**
* The `api` field pins `"1.0.0"`, the entry point is a plain file path, and there is no `"type":
  "module"` equivalent anywhere in the manifest schema. **[TYPINGS / DOCS]**
* This repo's own `build/build.mjs` already encodes the rule in a comment:
  `/** Sandbox bundle. Must be a classic script — the Figma sandbox has no module loader. */`
  with `format: 'iife'`. **[RAN — read from `build/build.mjs`]**

**Required output format: a single-file IIFE, no external imports, no `export` statements.**
Verified **[RAN]**: esbuild with `format: 'iife'` produces output beginning
`"use strict";(()=>{var h0={Black:{Civili…` and containing zero `import`/`export` statements.

### 6.5 Recommended esbuild configuration

The repo's `build/build.mjs` is already correct. Reproduced and annotated:

```js
// build/build.mjs
import * as esbuild from 'esbuild'
import { readFileSync, writeFileSync, mkdirSync } from 'node:fs'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const ROOT = join(dirname(fileURLToPath(import.meta.url)), '..')
const DIST = join(ROOT, 'dist')
const WATCH = process.argv.includes('--watch')
const DEV   = WATCH || process.argv.includes('--dev')
mkdirSync(DIST, { recursive: true })

const shared = {
  bundle: true,
  minify: !DEV,
  sourcemap: DEV ? 'inline' : false,   // inline: there is no file server for a .map
  legalComments: 'none',
  logLevel: 'info',
  define: { 'process.env.NODE_ENV': JSON.stringify(DEV ? 'development' : 'production') },
}

// (a) SANDBOX — dist/code.js
const mainCtx = {
  ...shared,
  entryPoints: [join(ROOT, 'src/main/code.ts')],
  outfile: join(DIST, 'code.js'),
  format: 'iife',            // ← MANDATORY. 'esm' will not load.
  target: ['es2017'],        // conservative; the sandbox is ES2020+, es2017 costs nothing
  platform: 'neutral',       // ← do NOT use 'node' or 'browser': no node builtins, no DOM
  mainFields: ['module', 'main'],
  conditions: ['import', 'default'],
}

// (b) UI — built in memory, then inlined into dist/ui.html
const uiCtx = {
  ...shared,
  entryPoints: [join(ROOT, 'src/ui/index.tsx')],
  outdir: DIST,
  format: 'iife',
  target: ['chrome100'],     // the iframe is a real modern Chromium
  platform: 'browser',
  jsx: 'automatic',
  jsxImportSource: 'preact',
  loader: { '.json': 'json', '.svg': 'text' },
  write: false,              // ← keep in memory so we can inline it
}

function inlineHtml(outputFiles) {
  const js  = outputFiles.find(f => f.path.endsWith('.js'))?.text  ?? ''
  const css = outputFiles.find(f => f.path.endsWith('.css'))?.text ?? ''
  const tpl = readFileSync(join(ROOT, 'src/ui/index.html'), 'utf8')
  writeFileSync(join(DIST, 'ui.html'),
    tpl.replace('/* __CSS__ */', () => css).replace('/* __JS__ */', () => js))
}
```

`src/ui/index.html` template:

```html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><style>/* __CSS__ */</style></head>
<body><div id="root"></div><script>/* __JS__ */</script></body>
</html>
```

Note the `.replace(..., () => css)` form — using a **function** replacement is essential, because a
string replacement would interpret `$&`, `$1` etc. inside minified JS. The repo already does this.

**Why `platform: 'neutral'` for the sandbox:** it stops esbuild from injecting Node shims or
assuming `window`/`document`. Verified **[RAN]** that bundling `milsymbol` this way yields only two
DOM references, both **inside the bodies of `asCanvas()` and `asOffscreenCanvas()`**
(`document.createElement("canvas")`, `new OffscreenCanvas(...)`) — never evaluated at module load.
**As long as we only ever call `symbol.asSVG()`, the bundle is sandbox-safe.** Never call
`asCanvas()`, `asOffscreenCanvas()`, or `asDOM()` from `code.js`.

### 6.6 `npm run package`

`manifest.json` + `dist/code.js` + `dist/ui.html` is the whole publishable payload. `build/package.mjs`
should zip exactly those three paths and nothing else.

## 7. The sandbox environment

### 7.1 Language level

*"ES2020 and beyond"* **[DOCS]**. Supported: *"classes with private fields and static blocks,
generators and async generators, `async`/`await`, destructuring, template literals, `for...of` loops,
modules"*, optional chaining `?.`, nullish coalescing `??`, logical assignment operators, `BigInt`,
typed arrays, `Proxy`, `Reflect`, `Symbol`, `Map`/`Set`/`WeakMap`/`WeakSet`, `Promise` (including
`allSettled`, `any`, `withResolvers`), `JSON`, `Math`, `Date`, `RegExp`, `structuredClone` **[DOCS]**.

The docs **do not name the engine** **[DOCS-SILENT]**. Target `es2017` in esbuild anyway — the size
cost is negligible and it removes an entire class of "works in dev, breaks for a user on an older
desktop build" bugs.

### 7.2 Globals: what exists

Authoritative, from `index.d.ts` **[TYPINGS]**:

```ts
declare global {
  const figma: PluginAPI
  const __html__: string
  const __uiFiles__: { [key: string]: string }
  const console: Console          // log, error, assert, info, warn, clear  — and nothing else

  function setTimeout(callback: Function, timeout: number): number
  function clearTimeout(handle: number): void
  function setInterval(callback: Function, timeout: number): number
  function clearInterval(handle: number): void

  const fetch: (url: string, init?: FetchOptions) => Promise<FetchResponse>
}
```

**So: `setTimeout` and `setInterval` DO exist in the sandbox.** The prose docs claim otherwise
(*"browser APIs like `XMLHttpRequest`, `fetch`, `setTimeout`, and the DOM are not directly available
from the sandbox"* **[DOCS]**) — **the docs are out of date and the typings are correct**, and
`closePlugin`'s own docstring confirms it: *"any `setTimeout` or `setInterval` timers will be
cancelled"* **[TYPINGS l.167]**. `fetch` likewise exists as a Figma-provided shim with a restricted
`FetchResponse` (`headersObject`, `ok`, `status`, `arrayBuffer()`, `text()`, `json()`), gated by
`networkAccess`. We use neither.

`console` is a **minimal** shim: only `log`, `error`, `assert`, `info`, `warn`, `clear`. **No
`console.table`, `console.time`, `console.group`, `console.trace`, `console.dir`.** Do not use them.

### 7.3 Globals: what does NOT exist

**No DOM whatsoever.** No `window`, `document`, `DOMParser`, `XMLSerializer`, `Element`, `Node`,
`HTMLCanvasElement`, `OffscreenCanvas`, `Image`, `Blob`, `File`, `FileReader`, `URL.createObjectURL`,
`localStorage`, `sessionStorage`, `XMLHttpRequest`, `WebSocket`, `Worker`, `requestAnimationFrame`,
`crypto.subtle`, `TextEncoder`/`TextDecoder` (assume absent), `atob`/`btoa` (assume absent).

**Direct consequences for this plugin:**

* **You cannot parse the milsymbol SVG with `DOMParser` in the sandbox.** Either (a) do the
  `<text>` extraction with hand-rolled string scanning in `code.js`, or (b) do all SVG
  parsing/manipulation **in the UI iframe** (which is a real browser and has `DOMParser`) and send
  the cleaned SVG + extracted text metadata over postMessage.
  **Recommendation: (b).** The iframe already needs to render a live preview, so it already has the
  SVG in a DOM. Have the UI produce `{ geometrySvg: string, texts: TextSpec[] }` and post that to
  the sandbox, which then only calls `createNodeFromSvg` + `createText`. This keeps `code.js` small
  and free of a bespoke XML parser.
  *Trade-off:* batch generation of hundreds of symbols then has to round-trip through the UI. That
  is fine — postMessage is fast and it keeps the sandbox responsive (§7.4).
* `figma.base64Decode` / `figma.base64Encode` exist on `PluginAPI` if you ever need byte work —
  prefer them over `atob`/`btoa`.

### 7.4 Performance: creating hundreds of nodes

**[DOCS-SILENT]** on hard numbers. Verified constraints and the mitigations:

1. **The sandbox is single-threaded and shares the main thread's event loop with the editor.** A
   synchronous loop creating 500 nodes will freeze the Figma UI for its whole duration and can trip
   the editor's unresponsive-plugin detection.

2. **Chunk with `await` yields.** Every `await` returns control to the event loop:

```ts
const YIELD_EVERY = 25

async function generateMany(specs: SymbolSpec[]) {
  const made: SceneNode[] = []
  const note = figma.notify(`Generating 0/${specs.length}…`, { timeout: Infinity })
  try {
    for (let i = 0; i < specs.length; i++) {
      made.push(buildOne(specs[i]))                 // synchronous, fast
      if (i % YIELD_EVERY === YIELD_EVERY - 1) {
        note.cancel()
        figma.notify(`Generating ${i + 1}/${specs.length}…`, { timeout: Infinity })
        await new Promise(r => setTimeout(r, 0))    // ← yield; setTimeout IS available (§7.2)
      }
    }
  } finally {
    note.cancel()
  }
  figma.currentPage.selection = made
  figma.viewport.scrollAndZoomIntoView(made)
  figma.notify(`Created ${made.length} symbols`)
}
```

3. **`figma.skipInvisibleInstanceChildren`** **[TYPINGS l.109]**:
   > When enabled, causes all node properties and methods to skip over invisible nodes (and their
   > descendants) inside instances.

   *"Defaults to true in Dev Mode, false elsewhere."* And **[TYPINGS l.91]**: *"If your plugin does
   not need access to these nodes, we recommend setting `figma.skipInvisibleInstanceChildren = true`
   as that often makes document traversal significantly faster."* Set it **once at the top of
   `code.ts`**. It costs nothing for us (we never inspect hidden instance internals) and makes any
   `findAllWithCriteria` scan dramatically cheaper.

4. **Prefer `findAllWithCriteria` over `findAll(callback)`** **[TYPINGS l.7021]**:
   > When paired with `figma.skipInvisibleInstanceChildren = true`, this method can be hundreds of
   > times faster in large documents with tens of thousands of nodes.

5. **Batch property writes.** Reading a geometry property (`width`, `absoluteBoundingBox`) forces a
   layout flush. Write everything first, read once at the end. In particular do **not** interleave
   `appendChild` / `resize` / `.width` reads per node inside the loop.

6. **Set `figma.currentPage.selection` and call `scrollAndZoomIntoView` exactly once**, after the
   loop — each is a full editor-side operation.

7. **Avoid `resize()` in bulk** — *"Since this function applies constraints recursively … calls to
   this function could be expensive"* **[TYPINGS l.7355]**. Prefer `resizeWithoutConstraints`, or
   better, bake the size into the SVG before import (§8.3).

## 8. `createNodeFromSvg` gotchas: clipping, anchoring, exact sizing

### 8.1 The returned frame and `clipsContent`

`createNodeFromSvg` returns a `FrameNode`. `FrameNode.clipsContent: boolean` **[TYPINGS l.9318]**.

**The docs never state the imported frame's `clipsContent` value.** **[DOCS-SILENT]** Figma frames
default to `clipsContent = true`, and the SVG importer sizes the frame to the `viewBox`. **Any
geometry that extends beyond the viewBox will be silently clipped.** **[INFERRED — verify]**

This is a real risk for us: milsymbol's amplifier text and speed leaders *do* extend past the frame
octagon, which is exactly why the viewBox has a negative origin
(`viewBox="-55 18.5 362 153.5"` **[RAN]**). milsymbol computes the viewBox from its own bbox so it
*should* already enclose everything — but stroke half-widths and text metrics can overshoot.

**Always do this, unconditionally, right after import:**

```ts
const frame = figma.createNodeFromSvg(geometrySvg)
frame.clipsContent = false          // never silently clip a military symbol
frame.fills = []                    // the importer may add a white/transparent background
frame.name = `APP-6E ${sidc}`
```

### 8.2 Anchoring / placement

`createNodeFromSvg` gives no control over where the frame lands. **[DOCS-SILENT]** Treat its `x`/`y`
as undefined and set them explicitly. Place new symbols at the viewport centre:

```ts
const c = figma.viewport.center
frame.x = Math.round(c.x - frame.width  / 2)
frame.y = Math.round(c.y - frame.height / 2)
```

Remember §4.2: `appendChild` preserves *relative* position. If you re-parent the frame into a
container, set `x`/`y` **after** the `appendChild`, not before.

The symbol's meaningful anchor is **not** the frame centre — it is milsymbol's `octagonAnchor`, the
point that should sit on the map location. Measured **[RAN]** for SIDC `10031000141211000000`:

| `size` | svg `width`×`height` | `viewBox` | `octagonAnchor` |
|---|---|---|---|
| 20 | 31.6 × 27.1 | `21 18.5 158 135.5` | `{x: 15.8, y: 16.3}` |
| 60 | 94.8 × 81.3 | `21 18.5 158 135.5` | `{x: 47.4, y: 48.9}` |
| 100 | 158 × 135.5 | `21 18.5 158 135.5` | `{x: 79, y: 81.5}` |

`octagonAnchor` is already in **output pixels** and scales linearly with `size`. Store it so callers
can align symbols precisely:

```ts
frame.setSharedPluginData('app6e', 'anchor', JSON.stringify(sym.octagonAnchor))
```

### 8.3 Resizing to an exact pixel height while preserving stroke weights

**The short answer: do not resize in Figma. Bake the size into milsymbol before rendering.**

Measured facts about milsymbol's SVG **[RAN]**:

* The `viewBox` is **constant** for a given SIDC + option set, in milsymbol's native 100-unit space.
* `stroke-width` is **constant** in viewBox units (typically `4`, sometimes `3` or `5`).
* `width` / `height` = `viewBoxW × size/100`, `viewBoxH × size/100`. So `size` is a pure uniform
  scale: at `size: 100` the SVG is 1:1 with the viewBox; at `size: 60` the intrinsic scale is 0.6.

That means **everything, including stroke weight, scales together** when you change `size`. This is
exactly the behaviour we want, and it happens *before* Figma ever sees the file.

**Recipe A — preferred. Compute the milsymbol `size` that yields the target height.**

```ts
import ms from 'milsymbol'

function symbolAtHeight(sidc: string, opts: object, targetHeightPx: number) {
  // 1. probe at a reference size to learn the aspect for this SIDC + option set
  const probe = new ms.Symbol(sidc, { ...opts, size: 100 })
  const { height: h100 } = probe.getSize()          // e.g. 135.5
  // 2. size is linear in the output height
  const size = 100 * (targetHeightPx / h100)
  // 3. render once, at the exact size
  return new ms.Symbol(sidc, { ...opts, size })
}

const sym   = symbolAtHeight('10031000141211000000', {}, 96)
const frame = figma.createNodeFromSvg(stripText(sym.asSVG()))
frame.clipsContent = false
// frame.height is now 96 (±rounding) and every stroke is correctly proportioned.
```

No `resize()`, no `rescale()`, no stroke distortion, no constraint recursion cost.

**Recipe B — when you must resize an already-imported node: use `rescale`, never `resize`.**

```ts
const k = targetHeightPx / frame.height
if (Math.abs(k - 1) > 1e-6) frame.rescale(k)   // Scale Tool semantics: strokes scale too
```

* `rescale(scale)` is *"the equivalent of using the Scale Tool from the toolbar"* **[TYPINGS
  l.7386]**; the Scale tool scales strokes and blurs with the geometry **[DOCS,
  help.figma.com]**. Scale must be **≥ 0.01**.
* `resize(w, h)` does **not** scale stroke weights — a 4 px stroke stays 4 px while the symbol
  shrinks, which visually destroys an APP-6E symbol at small sizes. It also *"applies constraints
  recursively … could be expensive"* **[TYPINGS l.7355]** and carries the missing-font re-layout
  warning **[TYPINGS l.7357]**.
* `rescale` scales **from the top-left corner** **[TYPINGS l.7383]** — re-centre afterwards.
* Aspect ratio: `rescale` takes one scalar, so it can only match one dimension. Match **height**
  (APP-6E symbols are specified by frame height) and let width follow. If you need both, the
  requested box is not the symbol's aspect ratio and you must letterbox, not distort.

**Guard rails:**

```ts
if (frame.width < 0.01 || frame.height < 0.01) throw new Error('degenerate SVG import')
// resize()/resizeWithoutConstraints() require >= 0.01; rescale() requires scale >= 0.01
```

**Verify after import, always.** Figma's handling of the width/height-vs-viewBox mismatch is
undocumented **[DOCS-SILENT]**; if the importer ever ignored the `width`/`height` attributes and used
the viewBox dimensions instead, every symbol would come in at `size: 100`. So:

```ts
const expected = sym.getSize()                    // { width, height } in px
if (Math.abs(frame.height - expected.height) > 0.5) {
  frame.rescale(expected.height / frame.height)   // self-heal, and log it
  console.warn('SVG importer ignored width/height; corrected by rescale')
}
```

### 8.4 Other import-time hygiene

```ts
function normalizeImported(frame: FrameNode, name: string) {
  frame.name = name
  frame.clipsContent = false
  frame.fills = []                 // drop any importer-added background
  frame.strokes = []
  frame.constrainProportions = true
  frame.expanded = false           // collapse the layer tree; SVG imports are noisy
  return frame
}
```

Also consider `figma.createComponentFromNode(frame)` so each generated symbol is a reusable
component, then `combineAsVariants` across affiliations/statuses to produce a variant set. Order
matters: build all `ComponentNode`s first (empty component sets are not allowed **[TYPINGS
l.1818]**), then combine.

### 8.5 The one-time verification harness you must run

Everything marked **[INFERRED]** above collapses to a single 15-minute check. Build this as a
temporary dev command (`figma.command === 'probe'`) and run it once in the desktop app:

```ts

  ['plain frame + amplifiers', '10031000141211000000'],

for (const [label, sidc] of CASES) {
```
